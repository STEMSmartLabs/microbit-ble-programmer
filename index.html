Compatibility and safety notes
  • When the installed runtime hash and MakeCode program layout match, the app uses the fast Partial Programming Service.
  • When the runtime or layout differs, the app extracts the V2 application region and uses Nordic Secure DFU to replace the runtime and program together.
  • Full application DFU does not intentionally replace the SoftDevice, bootloader or interface-chip firmware.
  • The currently installed application must expose Buttonless DFU. The new HEX should also retain Bluetooth/DFU support for future wireless updates.
  • Keep the micro:bit powered and the browser tab open until completion. USB recovery may be required after an interrupted full DFU.

This will replace the installed application runtime and user program. The SoftDevice and bootloader are preserved.

Full DFU verifies bonded access on the current host and sends the Buttonless DFU command once. A positive command response or successful secured write is treated as confirmed. A failed write followed by a disconnect is treated as uncertain and checked once through GATT. A failed write without a reboot stops and asks you to reconnect or repair pairing. If several DfuTarg devices are nearby, power off or move the others away before using the manual selector.
